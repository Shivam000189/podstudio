## Step-by-Step Implementation Tasks

### Task 1: Install Supertest in Server
Install `supertest` and `@types/supertest` into `server/package.json`.

### Task 2: Implement REST API Route Tests
1. **`auth.routes.test.ts`:**
   - Test user registration endpoint returns 201 with valid token and user object.
   - Test validation errors return 400 with descriptive error message.
   - Test login endpoint returns 200 with JWT on correct password.
   - Test `/api/auth/me` with valid `Authorization: Bearer <token>` header returns user profile.
   - Test `/api/auth/me` without token returns 401.
2. **`room.routes.test.ts`:**
   - Test `POST /api/rooms` creates a new room code with 201.
   - Test `POST /api/rooms/:id/request-otp` rejects invalid email with 400.
   - Test `POST /api/rooms/:id/request-otp` returns 200 success message on valid email.
   - Test `POST /api/rooms/:id/verify-otp` returns `guestToken` on valid 6-digit code.
   - Test `POST /api/rooms/:id/verify-otp` returns 400/401 on wrong code.
3. **`recording.routes.test.ts`:**
   - Test `GET /api/recordings` returns array of recordings for authenticated user.
   - Test `PATCH /api/recordings/:id` updates title.
   - Test `DELETE /api/recordings/:id` deletes database record and triggers Cloudinary deletion.

### Task 3: Implement In-Memory Socket.IO Integration Tests (`socket.test.ts`)
1. Create a dynamic test HTTP server and bind Socket.IO instance on an ephemeral port (port 0).
2. Connect real `socket.io-client` clients:
   - Client A (Host) with creator JWT token.
   - Client B (Guest) with scoped guest JWT token.
3. Verify test cases:
   - **Authentication rejection:** Connect with no token or invalid token -> socket receives `auth-error` and disconnects.
   - **Room Join & Presence:** Host emits `join-room`; guest emits `join-room`; host receives `user-joined` event with guest socket ID.
   - **Targeted Signaling Relay:**
     - Client A emits `offer` with `{ to: clientB.id, sdp: 'fake-sdp' }`.
     - Client B receives `offer` with `{ from: clientA.id, sdp: 'fake-sdp' }`.
     - Client B emits `answer` with `{ to: clientA.id, sdp: 'fake-answer' }`.
     - Client A receives `answer` with `{ from: clientB.id }`.
     - Client A emits `ice-candidate` with `{ to: clientB.id, candidate: 'fake-cand' }`.
     - Client B receives `ice-candidate`.
   - **Host Grace Timer & Room Termination:**
     - Host disconnects: verify server does not immediately kill room.
     - Host reconnects within grace window: verify termination timer is cleared.
     - Host emits `end-room`: verify all room participants receive `room-ended` event.
